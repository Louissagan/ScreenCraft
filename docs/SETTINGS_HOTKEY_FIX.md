# 设置窗口打开后截图快捷键无响应

> 此修改现已收录于 0.9.3；下文保留开发阶段的验证记录。见 [发布说明](RELEASE_0.9.3.md)。

2026-11-07，工作区修复，未打包、未替换正在运行的 0.9.2。

原因是 `SettingsDialog.RecordRegisteredShortcut` 在设置窗口有焦点、但没有快捷键输入框正在录入时仍返回 `true`。全局快捷键管理器将其解释为“该按键已被录入”，因此不再执行截图、OCR 等原动作。

修复后仅正在聚焦的全局快捷键输入框接收录入，普通设置控件返回未处理，让原动作正常执行。设置窗口同时改为非模态单实例：截图流程临时隐藏并恢复它时，不再结束模态循环并销毁未保存内容；关闭设置时释放快捷键录入回调。

验证结果：

- 完整自动回归 **226 PASS / 0 FAIL**。
- 独立可见原生窗口探针 **9 PASS**：常规、截图、工具栏、OCR 与取色、关于、贴图页面有焦点时均放行截图动作；快捷键栏聚焦时只录入；临时隐藏／模拟截图窗口／恢复后草稿保留；设置隐藏时继续放行。
- 原生探针调用生产热键分发及录入逻辑，使用假的注册适配器，没有抢占用户正在运行程序的快捷键，也没有读取桌面或剪贴板内容。截图生命周期使用空白测试窗口，不冒充实际桌面捕获验收。

记录保存在 [证据目录](evidence/automated/settings-hotkeys/)，探针源码为 `tools/SettingsHotkeyProbe.cs`。完整回归中同步更新了旧工具栏固定 728 像素的断言，改为检查工具栏与属性栏均在客户区内，符合上一轮按屏幕可用宽度展开的行为。
