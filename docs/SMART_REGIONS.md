2026-11-07。依据用户提供的微信截图行为，扩展原有只识别顶层窗口的选择器；删除“关于”页“界面与交互参考 1Capture 公开资料；Windows 功能独立实现。”，项目来源记录继续保留在文档中。

## 使用

开始区域截图，将鼠标移到控件或内容区，会优先显示该位置较小的可用范围。滚轮向上选择更大的范围，向下返回更小范围，尺寸提示显示当前层数。单击确认，直接拖动仍按手动框选结果截图；调整和标注阶段不受滚轮吸附逻辑影响。

## 实现与边界

合并顶层窗口快照、客户区、可见原生子窗口及 UI Automation 控件矩形，过滤不包含鼠标、过小、越界及重复范围。使用物理屏幕坐标，支持负坐标显示器。只在冻结时记录的鼠标下顶层窗口中查找，避免把截图遮罩本身当成目标。

原生子窗口在首次命中时缓存。控件树查询按鼠标停留去抖，在独立 MTA 线程进行，最多一个工作线程和一个最新待处理请求，防止快速移动积压。首次查询可能只返回部分容器，允许一次后台重试；旧位置、拖动中及窗口关闭后的结果丢弃。查询步数和主动遍历时间有限制，但外部提供者单次调用本身可能延迟，线程不会因此阻塞截图界面。线程选择参照 [Microsoft UI Automation threading guidance](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-threading-issues)。

仅查询矩形和控件类型／可见性，不读取控件名称、文字、输入值，不操作目标应用。未使用图像分割、OCR 或云服务识别内部区域。自绘画布、图片内容、不开放无障碍结构的应用，以及权限较高的窗口，可能只有客户区／整窗候选。浏览器和 Electron 等不同应用的识别覆盖仍待实测，不能声称已达到微信完整效果。

## 验证

- 完整回归 **233 PASS / 0 FAIL**；最后探测预算与首次重试调整后，相关反馈回归 **37 PASS / 0 FAIL**。
- 原生合成窗口验证四层候选：`120×55` 按钮 → `620×360` 面板 → `822×593` 客户区 → `840×640` 整窗；滚轮放大、返回小范围通过。
- UI Automation 在该窗口返回包含鼠标的面板区域，精确按钮矩形来自 HWND。没有将面板检测冒充为 UIA 精确按钮检测。
- 同一选择器实例验证手动拖动及最终松手坐标，选择结果为 `265×188`，未被智能吸附覆盖。
- 单元检查覆盖负坐标、嵌套排序、去重、边界裁剪、慢查询期间仅保留最新请求。测试探针仅显示自己的窗口，背景使用合成 DIB，不读取用户桌面或剪贴板。
